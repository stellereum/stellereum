0. ЦЕЛЬ ПРОЕКТА (паспорт, кратко)
--------------------------------------------------------------------------------
Stellereum (Stellereum Network) — Ultra-High Performance L1 Multi-Blockchain.
Нативный токен STELL: стейкинг, газ, ИИ-агенты, системные расчёты.
Позиционирование: Lightweight, AI-Native, MEV-Resistant & Orderbook-Optimized L1.

Стек по паспорту (10 секций):
  1. Архитектура: акторная модель, бесконечный шардинг (мастерчейн+шардчейны,
     авто-split/merge), Bag of Cells / DAG (ячейки 128B, Patricia-деревья).
  2. AI-Native VM: SVM + zk-SNARK/zkML лёгкая верификация + session keys для агентов.
  3. Нативный Orderbook-Actor CLOB: системные контракты стакана в SVM, low-level
     инструкции, sys-calls обхода Patricia, QUIC до валидаторов, async matching.
  4. Micro-gas: дешёвые инструкции, лимиты глубины стакана как анти-спам.
  5. Shared-Liquidity Workchain + Shared Sequencer: атомарные кросс-шардовые tx,
     пруфы Меркла, tight coupling, shared sequencing для L2.
  6. MEV-preemption: пороговая подпись / Fast BLS на сборке блоков, запечатывание
     mempool до фиксации, БЕЗ TEE/SGX.
  7. Pipelined Execution + In-Memory State Engine: разделение консенсуса и
     исполнения, горячее состояние в RAM, фоновая запись (задумано io_uring),
     латентность 100-200 мс.
  8. Native Teleport Bridges: валидаторные шлюзы, timelocks/лимиты, zk-SNARK
     проверка, мосты TON/Arbitrum/Ethereum/Solana.
  9. Опциональная приватность: Pedersen commitments (Curve25519/Ristretto,
     AVX2/NEON), stealth-адреса, viewing keys, БЕЗ RingCT.
 10. Оракулы 3-tier: pull (Pyth/Red), DEX TWAP, stale protection, circuit breaker,
     USDT-peg.

Токеномика: hard cap 1 000 000 000 STELL; genesis $0.25; распределение:
25% Genesis Vault, 15% Liquidity, 35% Validator Rewards, 15% Ecosystem, 10% Team.
Отказ (НЕ строить): Stellereum Storage, Proxy/анонимайзеры, нефинансовые сервисы,
TEE/SGX, RingCT/Monero-style тяжёлые пруфы.

   chain-id enforcement против конфига ноды, накопление бюджета в блоке
   несколькими tx (частично есть).

B) ШАРДИНГ + ОРАКУЛ (планы M1/M2/M3, из памяти §10.12).
   Шардинг: один процесс = два run_consensus_node (shard 0 и 1) на одном infnode
   Node (KV-межшард работает только внутри процесса!). consensus_topic сделать
   shard-scoped. НОВЫХ полей в Block нельзя (bincode) — использовать
   cross_shard_out как produces+consumes. ShardRegistry из env, все проверки
   под `registry.is_sharded()` (иначе старые тесты падают). M1: tx target_shard=1
   попадает в блок shard_id=1. M2: перевод 0->1 атомарно + replay-защита +
   равные root. Отдельные store/mempool пути на шард, иначе клоббер finalized.
   Авто-split/merge НЕ тащить в консенсус (недетерминирован по load).
   Оракул: УЖЕ СДЕЛАН on-chain (95df70c). Осталось: регистрация publisher'ов и
   сброс breaker'а через GovAction (сейчас тесты сидят set вручную); TWAP-тир
   остался в легаси-движке OracleSafetyEngine.

C) MEV + BLS (паспорт §6, оборванный агент): mev.rs (Shamir, seal/unseal/commit)
   и bls.rs (реальный BLS12-381, HybridCertificate) есть, но не в лив-пути.

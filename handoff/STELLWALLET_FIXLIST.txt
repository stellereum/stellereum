[АРХИТЕКТУРА — ГЛАВНОЕ]
2. Нет HTTP-RPC режима ВООБЩЕ. Кошелёк — in-process light client (свой движок
   состояния + опциональный P2P-адаптер через infnode). Юзер на ноутбуке НЕ
   может просто указать URL ноды: надо либо дописать RPC-клиент (образец —
   scripts/tps_load.py на stdlib: balance/nonce, sendRawTransaction, poll
   receipt, faucet), либо чинить P2P-коннект (конфиг пиров, endpoints стенда,
   DNS-federation). Без этого "поюзать на тестнете" = только с локальной нодой.
3. broadcast_tx врёт: статус "Confirmed" ставится ЛОКАЛЬНО сразу, без ожидания
   цепи. Добавить poll stell_getTransactionReceipt до FINALIZED (иначе юзер
   думает "ушло", а tx может висеть/отвалиться).
4. get_balance_spv проверяет пруф против СВОЕГО локального корня, а не цепи.
   Настоящий SPV: взять root + proof С НОДЫ (stell_getBalanceSpv / light-client
   пруфы есть на сервере) и сверить локально. Сейчас это SPV по форме.

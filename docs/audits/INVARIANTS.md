# INVARIANTS — the machine-checked security contract

> **Derived from the code, not from an audit report.** Every row below was
> produced by locating the implementing symbol in `src/` and the pinning test
> in `tests/` (or in a `#[cfg(test)]` module inside `src/`). Where a row says
> `OPEN`, it means **no automated pin was found in this tree** — that is the
> honest answer, and it is the list an auditor should attack first.
>
> **Anchor.** The `Implementation` column gives `file:line` **and** the
> symbol name. The symbol is the contract; the line number is a convenience
> that moves when the tree is edited. The line numbers in this file were read
> from the working tree at the fingerprint recorded in
> [`EXTERNAL_AUDIT_BRIEF.md`](EXTERNAL_AUDIT_BRIEF.md) §1.
>
> **Status vocabulary**
>
> | Status | Meaning |
> | --- | --- |
> | `PINNED` | a test exists in this tree that exercises the property, and that test was green in the measured run |
> | `PINNED (lib)` | the pin lives in a `#[cfg(test)]` module inside `src/`, not in `tests/` |
> | `PARTIAL` | the property is enforced on one path but not on every path that matters (the gap is named in the row) |
> | `OPEN` | enforced in code but **not** pinned by any test we could find |

## 6. Items that are **NOT** pinned (the auditor's shortlist)

These are properties the code enforces but where we could not find a named

targets for the external audit.

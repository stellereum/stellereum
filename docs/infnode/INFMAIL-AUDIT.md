## СВЯЗКА КРИТИЧЕСКИХ (проверено мной)

### 1. Полный обход 2FA
`crates/infmail/src/web.rs:1222` — при включённой 2FA логин отдаёт
`temp_2fa_token = jwt_sign(secret, email, 300)` — JWT **без claim `sid`**.

`web.rs:677-693` (`auth_email_sid`) — вся проверка сессии и эпохи лежит ВНУТРИ
`if let Some(sid) = &sid`. Нет sid → проверки пропускаются → `Ok((email, sid))`.

Итог: атакующий, знающий **только пароль**, получает temp-токен из `/auth/login`
и ходит с ним как `Bearer` куда угодно: почта, смена пароля, **выключение 2FA**.
2FA не защищает ни от чего.

### 2. Подпись кошелька не проверяется
`crates/infmail/src/nft/derive.rs:86-99` (`derive_x_pub_from_signature`) —
берёт 64 байта, считает `blake3(domain || sig)`, получает ключ. **Проверки подписи нет вообще.**

`web.rs:4071-4083` (`web3_save_keys`) — сверяет только `derived == присланный x_pub`.
Так как `derived` считается из той же присланной подписи, подходит **любые 64 байта**.

Итог: заявленная «криптопривязка писем к кошельку» (П3) **не криптографическая**.
С сессией можно перепривязать шифрование входящей почты на свой ключ.

**Цепочка: пароль → temp-токен (2FA мимо) → подмена x_pub → чтение входящей почты.**

> Это исправление моего же более раннего вывода: я раньше отчитался, что П3
> «завершён и работает». Те ручки работали, но криптография в них фиктивная.

## ЧТЕНИЕ ВСЕЙ ПОЧТЫ СЕТИ (проверено мной)

Чанки писем зашифрованы, но ключ расшифровки хранится рядом **открытым текстом**:

```
kv.json:  "key":"<64 hex>"  →  736 вхождений
          "key_box"         →  0 вхождений
```

- Код: `infnode/src/node.rs:2541,2544` (и `:2757,2760`) пишут `manifest["key"]`.
  Правильная ветка `box_wrap_key` есть, но продукт её не вызывает
  (`web.rs` использует `store_mail()` без box).
- `replicate_mail` (`node.rs:2592-2613`) рассылает манифесты **без проверки роли**
  (в отличие от чанков, где `peer_allows` есть).
- `K=20` (`dht.rs:9`), узлов 3–6 → рассылка всем.
- Валидатор принимает неизвестные ноды (`allow-unknown: true`), у TOFU-пира
  `storage_roles` пуст → `peer_allows` **всегда true** (`node.rs:2086-2096`),
  лимит запросов `0` = без лимита.

**Итог: подключился своей нодой — читаешь всю новую почту сети.**

## ОТВЕТЫ НА ТВОИ ВОПРОСЫ ПРО NFT

**Цены по длине (он-чейн `Registry.getPricing()`):**
| Длина | Цена |
|---|---|
| 1 символ | **0 TON, только админ** (`registry.tolk:59-66`, иначе throw 1005) |
| 2 / 3 / 4 / 5 / 6+ | 1 / 1 / 0.7 / 0.5 / 0.1 TON |

**Однобуквенное имя — можно, но только админом:**
- Контракт запрета на 1 символ не содержит — только gating по админу.
- Бэкенд `valid_email` (`web.rs:750`) 1 символ пропускает; **фронт блокирует**
  (`register/page.tsx:54-56`).
- Регистрация имени в Registry для минта **не требуется** — `Upgrade` не сверяется
  с Registry, админ может заминттить любой `emailHash`.
- **Стоимость ≈ 1.05–1.1 TON** (Upgrade 1 TON + Mint/деплой item ~0.05–0.1).
  Регистрация такого имени админом — 0 TON.
- Через сайт — нельзя (фронт блокирует).

**GetGems — сейчас не заработает.** Блокеры:
1. В контракте item content = `https://infmail.org/api/v1/nft/meta/`, а реальный
   роут бэкенда — `/api/v1/nft/{id}/meta` (другой порядок, нет index-суффикса) → **404**.
2. В JSON метаданных нет поля `image`.
Формально TEP-62/64 есть: `royalty_params` = 5% (denominator 100), transfer,
`get_nft_data`. Этого мало из-за пунктов 1–2.

**Состояние:** `nextItemIndex=4`; заминчены токены 0, 1, 3 (владелец — админ), слот 2 пустой.

**Кошельки:** проект **не создаёт** кошельки пользователям — только подключает
внешний через TON Connect. `derive.rs` — ключ шифрования, не кошелёк.

## ГОТОВНОСТЬ К MAINNET

**Завязано на testnet:** `blockchain.rs:10-11` (URL `testnet.toncenter.com`),
адреса контрактов в `web.rs`/`blockchain.rs` и в `infnode.service:32,34,36`,
на фронте `.env.local` + **хардкод Registry** в `register/page.tsx:267`,
`dashboard/page.tsx:205`, `add-account/page.tsx:265`.

**Риски миграции:**
1. Данные аккаунтов переносимы (ключуются по email, адреса контрактов внутри не зашиты).
2. **Wallet-логин сломается**: `check_registry_ownership` читает testnet-Registry;
   на mainnet записей нет → нужна batch-миграция или fallback на локальную БД.
3. **NFT теряются без пере-минта** — предметы живут в testnet-коллекции.
4. Нет `TON_API_KEY` → на mainnet будут 429.
5. Админ один, мультисига нет, `quorum=1`.

**Хорошая новость:** проверка подписи TON Connect **сделана правильно**
(ed25519-verify + домен + одноразовый nonce + срок) — кошелёк подделать нельзя.

## ОСТАЛЬНОЕ (кратко)

**Фронт** (`/home/imm/infmail-frontend-audit.md`, 34 функции):
- **Удаления аккаунта нет вообще** — ни UI, ни API.
- NFT-апгрейд в UI — только тост, платежа нет.
- Регистрация classic **бесплатно пропускает короткие имена** → обход монетизации.
- 7 ручек бэкенда не используются, при этом тариф обещает «15 aliases».
- Перф: все 8 страниц `'use client'`, поллинг 20с тянет весь инбокс,
  расшифровка всех писем O(n) на каждом обновлении, пагинация не используется.

**Сеть:**
- Порча данных / подделка proof-of-storage — **нет**, blake3-сверка работает честно.
- Но вредная реплика может **оборвать чтение** письма (после mismatch нет перебора).
- DHT-маршруты принимаются без аутентификации — в проде уже 3 ghost-записи.
- Бана плохой ноды нет; `trust_score` ни на что не влияет.
- Выплаты нодам **не идут**: «6182 pending — оператор не раздаёт».
- Нет lockfile на data-dir: два процесса в одном каталоге = потеря `kv.json`.

**Сделано хорошо:** Argon2+соль, JWT без `alg=none`, cookie HttpOnly+Secure+SameSite,
backup-коды sha256 одноразовые, rate-limit на логин/2FA/регистрацию/recovery,
path traversal закрыт, shell-инъекций нет, SSRF нет, секретов в git-истории нет,
горизонтального доступа по чужому email/id **не найдено**.

## ПОРЯДОК ИСПРАВЛЕНИЙ

1. **2FA-обход** (`web.rs:1222` + `677-693`) — не выдавать рабочий токен до 2FA;
   требовать `sid` обязательно, а не «если есть».
2. **Ключ в манифесте** (`node.rs:2541,2544`) — включить `box_wrap_key`,
   запретить `replicate_mail` без `peer_allows`.
3. **Права `accounts.json`** → 0600, бэкапы убрать/закрыть, `smtp_pass` шифровать.
4. **Секреты из systemd-юнита** → в отдельный файл 0600 / EnvironmentFile.
5. **Stalwart** → только HTTPS, убрать публикацию админки по HTTP.
6. **Подпись кошелька** (`derive.rs:86`) → реальный ed25519-verify против on-chain pubkey.
7. GetGems: починить путь метаданных + добавить `image`.
8. Удаление аккаунта (ни API, ни UI).
9. Mainnet-чеклист: RPC-ключ, batch-миграция Registry, пере-минт NFT.

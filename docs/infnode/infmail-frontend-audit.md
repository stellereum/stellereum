## 2. Баги и заглушки по важности

**P1 — функциональные дыры**

1. **Удаления аккаунта нет вообще.** Ни в Settings (`dashboard/page.tsx:700-1057`), ни в Topbar, ни в API-слое.
   Пользователь не может удалить аккаунт и данные; GDPR/«право быть забытым» не выполняется.
2. **Классическая регистрация обходит тарификацию.** Фронт считает цену по длине имени и направляет короткие имена
   в Web3 (`register/page.tsx:54-84`), но классический шаг (`143-167`) цену не показывает и `usernameValid`
   (regex требует ≥3 символов, `56`) не проверяет. На бэкенде `valid_email` (`web.rs`) ограничивает только
   `local.len() <= 64`, без нижней границы → 1–2-символьное имя вроде `ab@infmail.org` регистрируется
   **бесплатно**, минуя TON-оплату. Прямая потеря выручки + обход модели «короткие имена за TON».
3. **NFT-апгрейд — не покупка, а уведомление.** `handleNftUpgrade` (`dashboard/page.tsx:273-290`) получает
   `contract_address` и показывает нотификацию «Send 1 TON to …emailHash абракадабра…» с обрезкой до 8 символов;
   ни deep-link в кошелёк, ни QR, ни BOC/payload, ни опроса статуса. Для не-крипто-пользователя сценарий непроходим.
4. **Алиасы, шаринг файлов, сессии, подпись — есть на бэкенде, нет в UI.** При этом `PlanView.tsx:148-149,199-200`
   и `FilesView.tsx:300` активно обещают «15 email aliases». Обещание в тарифе не имеет точки реализации в продукте.
5. **Черновик нельзя сохранить без получателя** — `disabled={!to}` (`dashboard/page.tsx:1129`) при `handleSaveDraft`
   `553-555`. Типовой сценарий «набросать текст и дописать позже» не работает.
6. **Проверка занятости имени не вызывается.** `api.checkUsername` (`api.ts:80`) не используется ни в одной странице,
   хотя бэкенд-ручка с rate-limit есть (`web.rs:457`). Пользователь узнаёт «занято» только после сабмита,
   потеряв прохождение PoW (PoW сбрасывается: `register/page.tsx:165` `setPowState('idle')`).
7. **2FA: QR-код не показывается.** `setTotpQr(setup.qr_uri)` вызывается (`dashboard/page.tsx:604`), но `totpQr`
   нигде не рендерится — только ручной ввод секрета (`909`). Усложняет настройку, повышает число ошибок ввода.
8. **Ловушка в recovery.** Если у аккаунта нет методов восстановления, UI показывает нейтральное
   «If an account exists…» и **принудительно ставит method='email'** (`recovery/page.tsx:36-41`), после чего просит
   ввести код, который никогда не придёт, и предлагает задать новый пароль (`134-161`). Пользователь в тупике без пути назад.
9. **Ошибки проглатываются молча.** `dashboard/page.tsx:253` (`2FA status .catch(()=>{})`), `264` (NFT status),
   `269` (P3 profile); `useAppStore.ts:118,124,317` (quota/plan/counts); `keyManager.ts:82,182` (кросс-девайс ключи).
   Пользователь видит «пусто/0» вместо ошибки. Отдельно: сбой NFT-запроса сознательно трактуется как «неизвестно»
   (`api.ts:439-448`), но вызов на дашборде глушит результат (`264`).
10. **При единственном аккаунте истёкшая сессия выбрасывает без объяснения.** `http.ts:21-29`: на 401
    `removeAccount(activeAccountId)`; при последнем аккаунте состояние обнуляется, остаётся только тост на 5 с
    (`useAppStore.ts:98`), затем редирект на `/login`. `renewSessionCookie` вызывается только при `switchAccount`
    (`useAppStore.ts:181`), не перед запросами.

**P2 — UX/логика**

11. Даты в письмах локализуются на `ru-RU` (`api.ts:466`), при полностью английском UI → «14:30 сент. 14».
12. `disabled` на кнопке регистрации в add-account (`add-account/page.tsx:413`) не учитывает `strengthScore`
    (проверка есть только внутри обработчика `120`).
13. `handleChangePass` при успехе делает `setIs2FaEnabled(false)` (`dashboard/page.tsx:594`), хотя смена пароля
    2FA не выключает — UI временно врёт; другие сессии не инвалидируются.
14. Восстановление через 2FA и через backup-email: поле ввода одно, без маски/формата; нет счётчика попыток и
    «отправить код ещё раз» (`recovery/page.tsx:134-161`).
15. Нет пагинации почты: `fetchMails(token, folder, q, undefined, undefined)` (`useAppStore.ts:264`), при том что
    `api.ts:99-113` умеет `limit/offset` и бэкенд возвращает `{items,total}`.
16. Поиск дублируется: клиентский фильтр (`dashboard/page.tsx:61-67`) и серверный `q` в следующей загрузке
    (`useAppStore.ts:263`) — результаты не консистентны (ищет по загруженному срезу).
17. Повтор attach одного и того же файла не блокируется; дубликаты имён в списке вложений (ключ по индексу, `1116-1122`).

## 3. UX-состояния

**Есть и работает:** пустые состояния почты (`dashboard/page.tsx:1070-1074`), пустой Drive (`FilesView.tsx:308-314`),
заглушка Drive без подписки (`drive/page.tsx:33-51`), состояние загрузки файлов (`FilesView.tsx:306-307`), спиннеры на
кнопках (`Button.tsx`), тосты (`NotificationManager.tsx`), 5 с авто-скрытие (`useAppStore.ts:98`), ErrorBoundary на
весь апп (`ErrorBoundary.tsx`, `layout.tsx:34`).

**Проблемы:**
- `isMailsLoading` рисует **весь экран** спиннером (`dashboard/page.tsx:698`) — при обновлении ящика исчезают сайдбар,
  композер и открытое письмо. Дёрганый UX при каждом 20-секундном поллинге.
- Сообщение об ошибке показывается бэкендовым текстом без обработки (`err.message`), часть формулировок техническая
  («invalid email or password», «PoW verification failed»). Явного вывода `undefined` в UI не нашёл, но есть
  «0 B / 0» как маска ошибки (п.9 выше).
- Мобильная адаптация в целом сделана: `md:` брейкпоинты, drawer-сайдбар (`dashboard/layout.tsx:40-52`), скрытие
  списка/письма (`dashboard/page.tsx:1063,1161,1232`), `hidden sm:inline` подписи кнопок. Критичных поломок не видно.
- **Зум запрещён:** `viewport.maximumScale:1, userScalable:false` (`layout.tsx:22-26`) — прямое нарушение WCAG 1.4.4.
- Модалки: `Modal.tsx` — нет `role="dialog"`, `aria-modal`, фокус-трапа, автофокуса; закрытие — только Escape/клик
  по фону (`15-21, 42`).

## 4. Производительность

- **Все 8 страниц — `'use client'`** (`app/{page,login,register,recovery,plan,drive,add-account,dashboard}/page.tsx`),
  плюс `dashboard/layout.tsx`, `providers.tsx`. Серверного рендера данных нет: RSC не используется для загрузки данных,
  вся авторизация/данные — на клиенте. SSR/streaming-выигрыш не реализован.
- **Один динамический импорт на весь проект**: `keyManager.ts:221` (`import('./p3Integrate')`). Всё остальное —
  статически: `@ton/core`, `@ton/ton`, `@tonconnect/ui-react`, `tweetnacl`, `buffer`, `framer-motion`, `lucide-react`
  попадают в начальные чанки страниц, которые их импортируют. Ни одна тяжёлая панель не вынесена через `next/dynamic`.
- **Прод-бандл** (`/opt/infmail-web/.next`, замер на сервере): весь `.next` 79 МБ, `static` **2.0 МБ**,
  крупнейший JS-чанк **396 КБ** (несжатый), затем 240 КБ, 224 КБ, 164 КБ. HTML: `/` 25.9 КБ, `/login` 14.6 КБ,
  `/dashboard` 11.6 КБ (клиентский шелл). Для почтового веб-клиента — приемлемо, но без код-сплита по панелям.
- **`node_modules` 430 МБ**; `lucide-react` 39 МБ, `next` 202 МБ, `@tonconnect` 7 МБ, `framer-motion` 5.8 МБ
  (на диске; в бандле lucide/framer tree-shaken, но `framer-motion` тянется на `/`, `/register`, `/recovery`).
- **Поллинг 20 с** на `/dashboard` тянет полный инбокс + counts (`dashboard/layout.tsx:149-160`), даже когда
  открыто письмо или композер.
- **Расшифровка всех шифрованных писем списка** при каждом изменении `mails`: цикл `for` с await по каждому письму
  (`dashboard/page.tsx:317-346`) — O(n) крипто-операций на клиенте при каждом поллинге/смене папки.
- Кеш `sessionStorage` на аккаунт+папку (`useAppStore.ts:9-39`) и `prewarmAccounts` (фоновая догрузка Inbox **всех**
  аккаунтов, `277-292`) — при 8 аккаунтах это 8 параллельных `fetchMails`.
- `<img>` вместо `next/image` для NFT-карты и превью (`dashboard/page.tsx:783`, `FilesView.tsx:444`).

## 6. Сверка фронт ↔ бэкенд

**Фронт → бэкенд: расхождений нет.** Все ~55 вызовов из `api.ts` имеют соответствующие роуты в `web.rs:436-504`,
включая `/auth/verify-2fa`, `/settings/2fa/regenerate-codes` (маппится на `settings_2fa_backup_codes`, `web.rs:481`),
`/mail/{id}/attachment/{idx}/save-to-files`, `/keys/*`, `/web3/{derive,save}-keys`, `/nft/status|upgrade|verify|card`.

**Бэкенд → фронт: ручки, которые фронт не использует** (источник «недоделанных» фич):

| Ручка (web.rs) | Что не реализовано во фронте |
|---|---|
| `GET/POST /settings/aliases`, `POST /settings/aliases/delete` (`490-492`) | Создание/удаление алиасов — обещано в тарифах |
| `POST /files/{name}/share`, `GET /files/share/{token}` (`498-499`) | Шаринг файлов |
| `GET /settings/sessions`, `revoke`, `set-primary`, `revoke-all` (`485-488`) | Управление сессиями (методы в `api.ts:248-263` есть, UI нет) |
| `GET/POST /settings/signature` (`483-484`) | Подпись отправителя (в `api.ts:266-275` есть, UI нет) |
| `POST /settings/subscribe` (`473`, хендлер `4501`) | Фронт не вызывает: активация подписки идёт только через парсинг on-chain комментария (`nonce`-flow, `plan/page.tsx:63-83`) |
| `GET /web3/wallet-nfts` (`451`) | Не вызывается (используется `/web3/login` + `/web3/poll-activation`) |
| `GET /nft/{token_id}/meta` (`503`) | Не вызывается |

Отдельно: `GET /api/v1/admin/username/{user}/check` (`457`) реализован и отрейт-лимичен, но клиентская обёртка
`api.checkUsername` (`api.ts:80`) мёртвая — см. P1-6.

9. Заменить `user-scalable:false` — доступность — §5.
10. Убрать full-page спиннер на `/dashboard`, сделать скелетон списка — §3/§4.

--------------------------------------------------------------------------------
1. ЧТО ТАКОЕ STELLEREUM (один абзац архитектуры)
--------------------------------------------------------------------------------
Stellereum — L1-блокчейн на Rust поверх P2P-транспорта infnode (QUIC/TLS +
Kademlia DHT). Ядро — TON-стиль: акторная модель с bounce-семантикой, состояние
в Bag-of-Cells графах (128-байтные ячейки) поверх бинарного Patricia-Merkle
дерева cpat2, Masterchain (шард 0: конфиг, валидаторы, секвенсор, кросс-шард
хаб) + шардчейны с in-VM CLOB-стаканами. Исполнение — микросборщик SVM с
микро-газом (≈280k nano за перевод), Sealevel-lite параллелизм (DisjointScheduler),
нулевой оверхед MEV-преемпшн задуман пороговым (сейчас отложен, см. §3),
AI-натив: zkML-верификация + делегированные session keys, опциональная
конфиденциальность (Pedersen/Ristretto, stealth, viewing keys), 3-уровневый
оракул с circuit breaker, нативный Teleport-мост (кворум 2/3 distinct +
таймлок + rate limit), EVM-адаптер для MetaMask/Chainlist. Нативный токен STELL:
9 decimals (nano-STELL), hard cap 1 млрд (src/tokenomics.rs:13), Genesis Vault
250M STELL по $0.25 (25%), награды валидаторам 35% / 350M, ликвидность 15%,
экосистема 15%, команда 10% (12m cliff + 24m linear). Блок: ≤10 000 tx и
≤120M газа (src/runtime.rs:28,43). Подробнее: README.md, PROTOCOL.md,
docs/OPERATIONS.md, docs/RPC.md, docs/PERF_1K.md.

2. КОНСЕНСУС (BFT / PQ-BFT v5)
--------------------------------------------------------------------------------
Модель: классический BFT Tendermint-типа, per-height машина
`HeightConsensus` (src/consensus.rs:1793-1858): Propose → Prevote → Precommit →
Commit; финализация в `ValidatorRuntime::try_finalize` только по precommit-
кворуму ДЛЯ ТОГО ЖЕ блока, при обязательном prevote-кворуме за тот же блок
(PROTOCOL.md I4; регрессии `consensus::a_block_cannot_be_decided_on_precommits_alone`,
`a_locked_validator_will_not_decide_a_different_block`).
Безопасность: Tendermint-locking — залоченный валидатор не prevote/precommit
чужой блок (`decide_prevote`, src/consensus.rs:1898; lock: (hash, round),
src/consensus.rs:1821). Equivocation-доказательства дедуплицируются по паре
конфликтующих голосов (PROTOCOL.md, `hunt_slashing.rs`).
Proposer schedule: детерминированный взвешенный round-robin по
отсортированным id — `(height + round) % total_power` (src/consensus.rs:738-768);
GCD-правка убрала зависание, когда scheduled proposer никогда не предлагает.
Принят любой раунд 0..=qc_round (re-proposed locked блоки, харденинг f7ba7b8).
Кворум: `quorum_power() = floor(2*total_power/3)+1` (src/consensus.rs:703).
При unit-power: N=1→1, N=2→2, N=3→3 (!), N=4→3, N=5→4 (таблица docs/OPERATIONS.md §5).
Т.е. сети 2 и 3 требуют 100% подписей — падение ЛЮБОГО валидатора = стоп цепи.
Таймауты: базовый раунд-таймаут `STELL_ROUND_TIMEOUT_MS` (дефолт 3 с — OPERATIONS §4
«view change … каждые 3 секунды», PERF_1K §3), backoff +500 мс/раунд с капом
+10 с (src/main.rs:598-607); производственный пол `STELL_MIN_BLOCK_MS`
дефолт 400 мс (testnet/genesis.env:151), 0 = снять. Сообщение пира двигает
раунд максимум на +1; раунды двигаются только по СОБСТВЕННОМУ таймауту
(`next_round`), никогда по чужому клейму (защита от round-DoS, hunt_round_dos).
Deadlock breaker (f7ba7b8): `STELL_DEADLOCK_TIMEOUT_SECS` (дефолт 300, src/main.rs:3843):
прыжок к max(peer rounds), stale-голоса питают round-sync; тесты
tests/deadlock_breaker_tests.rs 5/5.
µQC / Tier-1 финальность (PQ-BFT v5): компактный комитет k=16 через BLAKE3
stake-weighted sortition (src/consensus.rs:345,462-485), порог
`pq_micro_quorum_threshold(k) = floor(2k/3)+1` → 11/16 (src/consensus.rs:450-459).
Маркеры в QC: `PQ_UQC_MARKER_ID=[0xFD;32]` (блочный µQC),
`PQ_QC_MARKER_ID=[0xFE;32]` (эпохальный CEC), wire-конверт `QC_UQC_MAGIC`
(src/consensus.rs:334-338). ВНИМАНИЕ (честно, урок ночи 13→14.10): при N≤16
комитет = весь сет, т.е. эффективный порог — UNANIMOUS 3/3 при N=3, строже
power-математики; флаг `fragile=false` при 2000/2000/1000 вводил в заблуждение
(docs/handoff/STELLEREUM_SESSION_2026-10-14.txt §6.2). План: power-weighted
PQ-кворум вместо поголовного µQC (§10).
Tier-2: Compact Epoch Certificate раз в 128 блоков (MMR-корень эпохи, весь состав)
— для мостов/крупных переводов (мастер-спек v5 §3.2). Голоса: по дефолту Ed25519
QC (`qc_bls_enabled()`), BLS12-381 — настоящий пэринговый (48B G1 ключи, 96B G2
подписи, `e(sig,G1)==e(H(m),pk)`, src/bls.rs, PROTOCOL.md) — opt-in; битвектор
сайнеров обязателен (его ест downtime-slashing). Timestamp-кламп:
`parent_ts..=parent_ts+3600` (MAX_TIMESTAMP_JUMP_SECS, src/runtime.rs, сессия
13.10 §1.4) — лечит рассинхрон после многочасового стопа.

428 plain-переводов (428×280k=119.84M ≤120M; 429-й не лезет — tests/packing_1k_tests.rs:28);

НЕ бутылочное горлышко. Симулятор: первый блок ~1.66 мс (README). V5-спек:
250k tx/s in-engine, 15 мс/блок (исторический замер; старый harness: Token
~613k tx/s, Native ~26k tx/s). E2E: 211 TPS замерено на стенде (REMAINING, сюит
1146/0); live-финализация сейчас ~1–2 с/блок (A/B; была ~0.95–1 бл/с до C-шторма).
Рецепт 1k TPS: 428 tx / 0.427 с ≈ 1002 TPS — закрывается EITHER back-to-back
полными блоками на полу 400 мс (1070 TPS), OR MAX_BLOCK_GAS 280M (1000 tx @1с),
OR mix 600 tx @600 мс (PERF_1K §3). Confidential-оговорка: Transfer2 verify
8.94 мс (32-bit) / 12.89 мс (64-bit) serial — блок с долей shielded f требует
8.5мс+f·428·11мс: f=10% ~55 мс (влезает), f=100% ~4.7 с (~90 TPS) — proof-bound;
лечится 32-битными пруфами (prove_auto) и batch_verify. Что ограничивает
сейчас: (1) транспорт/gossip — DHT-фоновый хвост p90 ~8.9 с, консенсус-хвост
убит; (2) этаж раунда MIN_BLOCK_MS 400 + тик ~460 мс = ≥0.66 с/высота минимум,
снижать только после падения resp (p50 ~660 мс vs таймаут 800 мс — запаса нет);
(3) шардинг выключен на стенде (STELL_SHARDS не задан) — весь TPS через один
шард; (4) слабые ноды (C: 1 vCPU) + шторм стримов давали 2.6→26 с/блок до
bound'ов fetch-8/snapshot-2/serial-чанков.

11. ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ И РИСКИ (честно)
--------------------------------------------------------------------------------
1) 2/2 хрупкость: при N=2 кворум=2 — падение/лаг ОДНОГО = стоп цепи; survivor не
деградирует в соло, sync тоже gated кворумом; «убить ноду чтобы survivor пошёл» —
не работает (OPERATIONS §5). 2) Unanimous µQC при N=3: комитет=весь сет → 3/3;
fragile=false при 2000/2000/1000 вводил в заблуждение; C-критичен пока голосует.
3) Slash-eject у MIN: downtime 0.1%/10 miss довёл C 1000→902 → eject; генезис-
валидатор на MIN живёт в ~100 STELL от изгнания — доливать с буфером ≥100.
4) A/B-рассинхрон r1550 vs r318: капы +8/4с + stale/absurd-дропы = взаимная
глухота навсегда; лечится только скоординированным рестартом (дроп bodyless-
локов + r0). 5) Перезапуск воскрешает stale round (checkpoint.round) — два узла
после deadlock рестартуют в разных раундах; recovery = wipe ОБОИХ data dir
сразу (PROTOCOL.md). 6) Retro-publish bounded (30с, 128/проход, глубина 4096):
узел, отставший глубже, с этого пира не догонится. 7) Рост диска: archive по
дефолту БЕЗГРАНИЧЕН (2.9GB замер; ~216k блоков/сутки при 400мс; хвосты
~2.5–3.5GB/мес; C на 4.5G ≈1.5 мес); prune STELL_ARCHIVE=0 + KEEP (конвергенция
постепенная, 20k/проход); снапшоты каждые 100 высот тоже копятся; метрики диска
НЕТ (только du/alert на дериватив); persist-queue 8192 дропает при медленном
диске (stderr, не tracing — Kat пропустят). 8) chain_id=5757 hardcoded — не
разделяет testnet/mainnet одного бинаря; разделять на сети. 9) Faucet-ключ —
ed25519 seed в env/процессе в открытом виде, тестовый 0x11..11 публичен;
STELL_FAUCET_KEY обязан совпадать байт-в-байт (иначе тихий сплит); пустой dir
стартует новую цепь МОЛЧА (guard ловит только рестарты). 10) Приватность ≠
анонимность: отправитель всегда публичен, скрытый получатель — только с
гигиеной; F-A открыт (минус-балансы легальны). 11) Мемпул не переживает рестарт
→ faucet nonce-gap (резерв сгорел, on-chain не догнал); чинится clamp-down +
reconcile mex + spill каждые 15с/SIGTERM. 12) Приёмка блоков best-effort с
одной строкой отказа; proposal-reject виден только в info. 13) stell_syncing —
vantage-local (партиция = false). 14) BLS QC opt-in — при 100+ валидаторах
Ed25519-сертификаты толстые; µQC-16 держит 250 валидаторов при 250мс–1с, но
только после power-weighted переделки. 15) Товарный знак «Stellar» не проверен;
stellereum.org куплен (.org).

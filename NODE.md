# Stellereum — Community Node Guide (public testnet)

Audience: a stranger with 1 vCPU who must join and stay synced.
Chain id `5757` is known (`stellereum/src/zkml.rs:220` `DEFAULT_CHAIN_ID`, env `STELL_CHAIN_ID` `:226`, frozen in `stellereum/src/consensus.rs:49-69`).
Public endpoints / faucet URL / token / peer list: `TBD-operator` (ask the network admin; never guess).

## 1. Requirements (plausibility, not promises)

- `1 vCPU / 2 GB RAM / 20 GB disk` is plausible for an observer/full node:
  - Observed RSS is tens of MB per node; units cap at `MemoryMax=2G` and `CPUQuota=80%` with the comment that the live box has 1 vCPU (`stellereum/scripts/systemd/stell-nodeA.service:32-40`, identical `stell-nodeB.service`; `scripts/join-network.sh:389-392` repeats the same cap/rationale).
  - No swap claim is made anywhere in code; no minimum-disk const exists. `20 GB` is an operator floor for `./data/store` (sled) + journal + one binary (~tens of MB) + log rotation. Prune mode keeps `STELL_KEEP_BLOCKS=1000000` by default (`scripts/join-network.sh:89,340`); archive nodes grow without bound — disk-guard warns at 80%/90% (`scripts/join-network.sh:455-459`).
- Ports (all in `stellereum/Dockerfile:36-38`, `stellereum/docker-compose.yml:15-17`):
  - `9410/udp` QUIC P2P (must be reachable inbound; `join-network.sh` opens it or prints the command `:471-487`).
  - `8545/tcp` JSON-RPC, `8080/tcp` explorer/gateway. Bind loopback (`127.0.0.1:8545`) unless you set `STELL_RPC_AUTH_TOKEN` (+ `STELL_FAUCET_TOKEN` if faucet on) — fail-open warning is in `Dockerfile:42-44`.
- Verified present: `stellereum/Dockerfile`, `stellereum/docker/node.yaml`, `stellereum/docker-compose.yml`, `stellereum/scripts/systemd/stell-nodeA.service`, `stell-nodeB.service`, `stellereum/scripts/join-network.sh`, `stellereum/scripts/add-peer.sh`, `stellereum/scripts/backup/backup.sh|restore.sh`.

## 2. Install

### A. Binary release path
```bash
git clone <TBD-operator repo URL> && cd stellereum-project/stellereum
cargo build --release --bin stellereum
./target/release/stellereum --help
./target/release/stellereum run --help
./target/release/stellereum wallet --help
./target/release/stellereum keys --help
./target/release/stellereum node-bootstrap --help
```
`join-network.sh` auto-detects `target/release/stellereum` or builds it (`scripts/join-network.sh:153-169`).

### B. Docker path
```bash
# build context MUST be the parent dir (blockchain + infnode dep): Dockerfile:4-8
docker build -f stellereum/Dockerfile -t stellereum/node .
docker compose -f stellereum/docker-compose.yml up
# or: docker run -p 9410:9410/udp -p 8545:8545 stellereum/node
```
Runtime image copies the binary to `/usr/local/bin/stellereum` and the example config to `/opt/stellereum/node.yaml`, entrypoint `run --config /opt/stellereum/node.yaml --shard 1` (`Dockerfile:32-49`). Volumes: `/opt/stellereum/data`, `/opt/stellereum/keys`. Compose defaults RPC/explorer to loopback (`docker-compose.yml:27-28`).

## 3. Config — minimal `node.yaml` (annotated)

Start from `stellereum/docker/node.yaml` (full file is 20 lines):
```yaml
name: stellereum-node
listen: "0.0.0.0:9410"      # QUIC listener; open UDP 9410 inbound
advertise: "TBD-operator-IP:9410"  # what others dial; autodetect warns behind NAT (join-network.sh:238-248)
storage-roles: [mail, files]
peers: []                   # FILL from admin --peers-file; empty = solo genesis = SPLIT (join-network.sh:277-281,352-355)
validators: []              # FILL with the network CURRENT set; empty = solo genesis (bootstrap.rs:102-104)
allow-unknown: false        # public testnet: false + pinned validators. Example ships true (TOFU dev only); dns_seeds.rs:48-49 says mainnet MUST be false
```
Env file (`node.env`, `0600`, generated by `join-network.sh:326-350`):
```bash
STELL_FAUCET_KEY=<64hex SAME on every node — genesis input; mismatch forks silently>
STELL_OBSERVER=1            # fresh joins ALWAYS start as observer (join-network.sh:21-23, bootstrap.rs:91)
STELL_DNS_SEEDS=TBD-operator # discovery only, never validators
STELL_RPC_LISTEN=127.0.0.1:8545
STELL_EXPLORER_LISTEN=127.0.0.1:8080
STELL_FAUCET=0              # enable on ONE node per network at most
STELL_RPC_AUTH_TOKEN=TBD-operator-if-exposed
STELL_FAUCET_TOKEN=TBD-operator-if-faucet-on
STELL_CHAIN_ID=5757
```
Keys live in `./keys` (`0700` dir, `0600` files; `keys init` is idempotent). Data defaults to `./data` (`--data-dir ./data` on `node-bootstrap`); never `cp -a` another node's `data/` — foreign store = foreign genesis fingerprint = silent split (`join-network.sh:149-151,502`).

One-command alternative (verified script, read its `--help` first):
```bash
stellereum/scripts/join-network.sh --faucet-key <64hex> --peers-file <admin file> --home ~/stellereum-node
```

## 4. Run

```bash
cd ~/stellereum-node && set -a; . ./node.env; set +a
# preflight only:
stellereum node-bootstrap --config node.yaml --shard 1 --no-exec
# real first start (gate passes -> execs into run; same code path):
stellereum node-bootstrap --config node.yaml --shard 1
# restarts use run directly:
stellereum run --config node.yaml --shard 1
```
Systemd: copy/adapt `stellereum/scripts/systemd/stell-nodeA.service` (shard 1, RPC `127.0.0.1:8545`, P2P UDP `9410`) or the `join-network.sh`-generated unit (`[Service] ExecStart=$BINARY run --config node.yaml --shard 1`, `WorkingDirectory=$HOME_DIR`, `EnvironmentFile=node.env`, `Restart=always`, `RestartSec=5`). Inspect with `journalctl -u <service> -e`, `systemctl reset-failed`.

## 5. First sync — what to expect

- Fresh observer + clean dir + `STELL_OBSERVER=1` + live peer + non-empty `validators:` or the gate refuses loudly (`src/bootstrap.rs:76-106`; `fresh_join_refusal_message` `:136-147`).
- Engine picks by gap (`src/bootstrap.rs:54` `BOOTSTRAP_SNAPSHOT_GAP=100`; `src/main.rs:1626` `TAIL_ANCHOR_GAP_THRESHOLD=50`; `:2271` gap `>256` skips body walk in favor of snapshot):
  - gap ≤ ~100: body walk from your tip.
  - gap > ~100: snapshot-sync — newest 100-boundary snapshot, header-anchored (`B+1` commits to post-`B` state), root-checked before commit (`src/main.rs:1575-1600`).
- Watch: `journalctl -u <service> -f` for `[sync] fast-synced state from a snapshot at height {boundary}` (`main.rs:1943`), then `[sync] caught up`. Compare `stell_blockNumber` + `stell_getStateRoot` against a live peer: equal roots at equal heights = same chain.
- Wall-clock: `TBD-operator` (depends on snapshot size, peer uplink, disk). Do not publish estimates; snapshot interval default is 1000 blocks (`src/main.rs:264-266` `STELL_SNAPSHOT_INTERVAL`).

## 6. Upgrade (binary swap + rollback)

```bash
systemctl stop <service>
cp -a ~/stellereum-node/data ~/stellereum-node/data.bak.$(date -u +%FT%TZ)
cp -a ~/stellereum-node/keys ~/stellereum-node/keys.bak.$(date -u +%FT%TZ)
cp ~/stellereum-node/node.env ~/stellereum-node/node.env.bak.$(date -u +%FT%TZ)
cp $(command -v stellereum) /opt/stellereum/stellereum.prev
# swap:
cargo build --release --bin stellereum && install -m755 target/release/stellereum /usr/local/bin/stellereum
# or: docker pull <TBD-operator image> && docker compose up -d
systemctl start <service> && journalctl -u <service> -e
# rollback: stop, restore binary (.prev) + data/keys/env backups (or scripts/backup/restore.sh), start
```
Never delete `data/store`, `data/kv.json`, or the running binary as "cleanup" (constitution §6); never wipe a single file inside `data/` — wipe the whole `./data` only for a fresh bootstrap (`bootstrap.rs:97`).

## 7. Troubleshooting — top-5 real log signatures (grep-verified)

1. `[chain-id] REFUSING: peer reports chain id {peer} but this node is {local} …` (`src/zkml.rs:258-263`; frozen id `src/consensus.rs:61-69`). Fix: set `STELL_CHAIN_ID` to the network's id (`5757` testnet), point at same-chain peers.
2. `rejected: transaction chain-id mismatch: envelope binds chain {} but this chain is {chain_id}` (`src/consensus.rs:145`). Fix: sign with `--chain-id 5757` / correct network; resubmit.
3. `genesis state root mismatch {scope}: expected … found …` (`src/bootstrap.rs:330-338`, surfaced `src/main.rs:483,7920`). Fix: `STELL_FAUCET_KEY` / `validators:` / peers differ from network — copy admin's file byte-for-byte; wipe whole `./data` and re-bootstrap as observer.
4. `STELL_OBSERVER!=1 (a fresh key without the observer flag mints its own genesis and splits)` (`src/bootstrap.rs:91`) / `[bootstrap] REFUSING: fresh/empty data directory BUT peers/DNS seeds are configured …` (`:138-146`). Fix: fresh join with `STELL_OBSERVER=1` + `node-bootstrap`; never mint a validator genesis against peers.
5. `[sync] snapshot at {boundary} rejected: …` / `[sync] REFUSING snapshot at {boundary}: … successor header does not link …` / `[sync] snapshot-fetch {bucket}/{name}: … unavailable …` (`src/main.rs:1780,1882`; `src/network.rs:1506-1536`). Fix: wait/retry (poisoned-or-rotated boundary auto-advances after `BOOTSTRAP_MAX_STALE_PER_BOUNDARY=3`, `bootstrap.rs:59`); check peer reachability + UDP 9410 + disk; `data directory is NOT clean …` means use `--allow-dirty` only for restarts.
